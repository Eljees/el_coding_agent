## 2. Дефекты и несоответствия

### 🔴 Критичные

**D1 — Makefile coverage floor 65% vs CI 80%**
- `Makefile: pytest --cov-fail-under=65`
- `.github/workflows/ci.yml: --cov-fail-under=80`
- Локальный `make test` не отловит деградацию между 65% и 80%.
- **Исправление:** `sed -i 's/cov-fail-under=65/cov-fail-under=80/' Makefile` (1 строка).

**D2 — GitLab CI floor 65% vs GitHub CI 80%**
- `.gitlab-ci.yml` использует `--cov-fail-under=65`.
- GitLab-пуши проходят при покрытии 70%, хотя стандарт проекта — 80%.
- **Исправление:** заменить в `.gitlab-ci.yml` так же.

**D3 — 5 значимых коммитов не влиты в origin/main**
- Ветка `test/artifact-unpack` содержит: observability (Runs tab, attempt timeline), lessons (CURATED_PITFALLS, record_lesson), rules (AGENT_RULES.md), interactive clarifications (-i/--interactive), appsechub trend routing + smoke checkbox.
- Это полноценные фичи, а не тест-артефакты.
- Название ветки не отражает содержимое.
- **Решение:** согласовать merge в origin/main (GitLab), затем GitHub.

### 🟠 Значимые

**D4 — CHANGELOG.md не обновлён для последних 5 фич**
- В `[Unreleased]` нет записей о lessons, rules, observability/Runs tab, --interactive, appsechub trend, smoke-after-apply.
- Коммиты с `feat(...)` без соответствующих changelog-записей.

**D5 — safety.py 88% — 5 непокрытых строк в критическом модуле**
- Строки 63 (`normalize_path`), 81 (`is_sensitive_path`), 89 (`can_read_path` вариант с sensitive), 106-107 (`run_command` → `subprocess.run`).
- Мутационное тестирование (mutmut) покрывает safety.py, но pytest-ветки непокрыты.
- **Риск:** `run_command` реальный путь исполнения команд не покрыт тестами.

**D6 — safety.py не проверяет Windows-специфичные деструктивные команды**
- Нет паттернов для: `rd /s /q`, `rmdir /s`, `takeown /r`, `icacls /reset /t`.
- Проект целевой для Windows/PowerShell, но safety.py имеет только POSIX + PowerShell Remove-Item.
- Строки добавить в `_DANGEROUS_COMMAND_PATTERNS`.

**D7 — planner.py 1175 строк / 83% — 70 строк не покрыты**
- Непокрытые пути: строки 223-262 (repair_patch_with_error пути), 432-466 (ревизия плана с answers), 592-612, 812-813, 929-985 (edge cases в make_patch/make_plan).
- Самый большой файл — кандидат для разбиения или дополнительных тестов.

**D8 — `type: ignore` без квалификатора в capabilities.py:314**
- `eps = _metadata.entry_points().get(...)  # type: ignore` — нет `[...]`.
- mypy strict mode принимает это сейчас, но `ruff` или будущие версии mypy могут флагнуть.
- **Исправление:** уточнить до `# type: ignore[attr-defined]` или аналога.

**D9 — Python 3.13/3.14 не в CI матрице**
- У пользователя установлен Python 3.14 (путь `C:\Python314\`), и `prompts.cpython-314.pyc` существует в __pycache__.
- CI тестирует только 3.11, 3.12.
- Python 3.13 stable вышел в октябре 2024, уже пора добавить в матрицу.

### 🟡 Незначительные

**D10 — retrying.py 83% / строки 31-33 не покрыты**
- Строки 31-33 — ветка HTTP 400/413 с "context too large" в теле ответа.
- Нужен один тест с `httpx.HTTPStatusError(status_code=413, response=...)`.

**D11 — targeting.py 85% / строки 55-62, 70 не покрыты**
- Строки 55-59 — обработка абсолютного пути внутри workspace → `.relative_to()`.
- Строки 61-62 — абсолютный путь вне workspace → `None`.
- Строка 70 — `_detect_mode` возвращает "unknown" (нет ни create ни update hint).

**D12 — skill_registry.py 90% / строки 22, 29, 55, 59, 69, 78 не покрыты**
- Пути: path_has_blocked_dir=True, frontmatter без `---`, body без heading, body без нестрочных линий.

**D13 — runner.py:108 `real_stdout=None` без type annotation**
- `def _run_task_body(task: str, args: argparse.Namespace, *, json_mode: bool = False, real_stdout=None)`
- mypy strict должен флагнуть это как `Any`. Либо явно `real_stdout: IO[str] | None = None`.

**D14 — ui_helpers.py 57 строк / 18% — Tk-зависимые функции без тестов**

## 3. Архитектурные замечания

**A1 — planner.py 1175 строк — превышает разумный порог модуля**
- Содержит: make_plan, make_patch, repair_patch_with_error, revise_plan_with_answers, revise_plan_with_assumptions, suggest_commands, inject_guardrails, context builders.
- Кандидаты для выделения: `plan_context.py` (сборка контекста для LLM), `patch_builder.py` (make_patch + repair_patch).
- Это рефактор — не срочно, но плановый.

**A2 — ui.py 1005 строк / 15% — основной UI-долг**
- Осталось вынести: вкладки Runs/Capabilities (отображение истории, дерево capability).
- Цель: ui.py < 600 строк, чистый event-диспетчер.
- После разбивки coverage улучшится (новые модули тестируемы без Tk).

**A3 — Нет разделения `sessions/` vs `runs/`**
- `.local-codex-lite/runs/` содержит 25 папок за период май-июнь.
- `runs_admin.py` есть, но нет CLI-команды `runs cleanup --keep N`.
- Без периодической чистки директория будет расти бесконтрольно.

**A4 — `generated_projects/` в репозитории**
- 4 папки с агент-сгенерированными проектами в корне репо.
- В `.gitignore` — значит не пушатся, но засоряют рабочую директорию.
- Стоит добавить в `runs cleanup` или отдельную команду `projects cleanup`.

**A5 — Нет интеграционных тестов против реального LLM**
- Все тесты используют stub/mock LLM.
- Нет `tests/integration/` с тестами против локального vLLM эндпоинта (опциональные, помеченные `@pytest.mark.integration`).
- Это ок для CI, но полезно иметь для smoke-проверок перед релизом.
