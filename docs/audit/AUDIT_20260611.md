- Файл `docs/audit/` содержит 3 актуальных аудита + `archive/`. Без `README.md` неясно, какой актуальный.
- Фикс: добавить одностроковый `README.md`.

### 🔵 N3 — `suggest_commands` (runtime-fix путь) вызывает `client.chat()` без таймаута

`planner.py:488`: `response = client.chat(messages, ...)` — прямой вызов без `_chat_with_timeout`.
Это задокументировано в бэклоге ("suggest-commands timeout"). Остальные пути (repair, rewrite) уже
обёрнуты в `_chat_with_timeout`. Аналогично: `make_plan:87`, `make_review:548`,
`revise_plan_with_assumptions:608`, `revise_plan_with_answers:649` — без таймаута.
- Риск: зависание агента при недоступном vLLM или большом контексте.
- Приоритет: 🟠 medium (практически проявляется при сетевых сбоях).

### 🔵 N4 — `del /f <file>` (без `/s`) блокируется safety.py

`safety.py:23-24`: regex `\bdel\s+(?:/[sqf]\b\s*)+` перехватывает `del /f file.txt`
(принудительное удаление read-only файла, не рекурсивное). Комментарий говорит "del /s (and optional
/q, /f)", но паттерн срабатывает и на одиночный `/f`.
- Текущее поведение: **консервативно** (лучше лишний блок, чем пропуск).
- Возможная проблема: легитимные команды `del /f backup.tmp` будут отклонены агентом.
- Решение (опционально): уточнить regex до `\bdel\s+(?:/[sqf]\b\s*)*(?:/s\b)` — только если `/s` обязателен.
- **Согласовать с пользователем** перед изменением.

### ✅ N5 — Структура `scripts/__pycache__/` — не в git

`scripts/__pycache__/` содержит `.pyc` файлы но они в `.gitignore` → не трекируются. Всё чисто.
