## 1. Суть проекта и приоритеты

`local_codex_lite` — **локальный, приватный, безопасный по умолчанию** кодинг-агент (MVP) под Windows/PowerShell. Работает против локального OpenAI-совместимого vLLM (`http://localhost:8015/v1`, `qwen25-coder-14b-awq`), без облака.

Базовый цикл: задача → инспекция воркспейса и ранжирование файлов → план от LLM → генерация unified diff → валидация/нормализация/починка → превью → (`--apply`) применение с бэкапом через `git apply` → пост-проверка AST → (`--exec`) запуск команд → логи и evidence в `.local-codex-lite/runs/<ts>/`.

Приоритеты (из `AGENTS.md`), по убыванию:

1. **Безопасность** — доступ только внутри воркспейса, блок чувствительных файлов и опасных команд, бэкап перед применением, никаких записей без `--apply`, никаких команд без `--exec`.
2. **Evidence-first** — доказательства (CVE/TruffleHog/артефакты) хранятся отдельно от правок.
3. **Маленький и читаемый core** — без тяжёлых фреймворков, новое поведение за явными флагами.
4. **Локальность и приватность**.

Плюс: система **capability-плагинов** (entry points), реестры tools/skills/intent, RAG (по умолчанию keyword), Tkinter-GUI.

## 2. Общая оценка здоровья

Проект **в хорошей инженерной форме**, это не «латание дыр»: двойной CI (GitHub + GitLab) с быстрым stdlib-гейтом, ruff/mypy запинены в lockstep (`ruff==0.15.15`, `mypy==1.14.1`), порог покрытия 65 %, мутационное тестирование 4 критичных модулей, тестовый прогон зелёный (~396 тестов на текущей ветке), живой `AGENTS.md`, чистая слоистость и тест-сим `SupportsChat` для планировщика. Циклических импортов и явных багов в основном пайплайне нет.

Поэтому ниже — **точечные** дефекты и долги, а не критические поломки. Самые ценные пункты — про **workflow/git внутри папки синхронизации** и **god-class `ui.py`**.

## 3. Дефекты и недостатки

Severity: 🔴 высокий · 🟠 средний · 🟡 низкий/нит.

### 3.1 Workflow и репозиторий

- 🔴 **Репозиторий живёт внутри живой синхронизации YandexDisk** (`D:\!ya_drive_sync\YandexDisk\...`). Прямое следствие, замеренное по факту:
  - **69** бэкап-локов в `.git` (`index.lock.bak*`, `HEAD.lock.bak.*`, `…proxy.commit`, `…kill` и т.п.);
  - **225** осиротевших `tmp_obj_*` в `.git/objects` (незавершённые git-операции);
  - `.pyc`-дубликаты конфликтов синхронизации: `cli.cpython-312 (2).pyc`, `trufflehog.cpython-312 (2).pyc`, `ui.cpython-310.pyc.131650975496112`, `*.pyc.bak`.
  Это копит риск повреждения индекса/объектов и тормозит файловые операции (во время анализа bash-таймауты на `find`/`grep`). **Это самый важный пункт.**
- 🟠 `tests/test_runner_apply.py` числится **untracked** в git (`?? tests/test_runner_apply.py`) — критичный для apply-пути тест может не попадать в коммиты/CI у тех, кто клонирует.

### 3.2 Архитектура и код

- 🔴 **`ui.py` — god-class** (1209 строк, ~61 метод, `CommandCenterUI`). Смешивает Tk-вёрстку, потоки, переключение cwd (`temporary_cwd` через глобальный `os.chdir`, строки ~902–979) и доменные эвристики (`cve_min_severity_for_task`, `should_create_project_workspace`), которым место в доменном слое. Единственная реальная слабость разделения ответственности; ~18 % покрытия.
- 🟠 **`planner.py` — 1118 строк** (крупнейший логический файл). Работает, но плотный; retry-варианты покрыты частично.
- 🟠 **`datetime.UTC` импортируется безусловно** (`logging_utils.py:8`, также `evidence_mode.py`, `rag.py`, `runs_admin.py`). На Python 3.10 пакет падает на импорте с сырым `ImportError` вместо понятного сообщения. Формально согласуется с `requires-python>=3.11`, но нет дружелюбного гварда версии.
- 🟡 **Мёртвая метадата `executor`** в `tool_registry.py` (строки ~39, 56, 76, 107): строки вида `local_codex_lite.cli.cmd_logs_latest` нигде не диспатчатся динамически (только печатаются в `ui.py:695`). Сгниёт молча, если убрать ре-экспорты из `cli.py`.
- 🟡 **`intent.py:71–73`** — `max(..., default=(0, capabilities[0], []))` индексирует `capabilities[0]`; при пустом `discover_capabilities()` будет `IndexError`. Сегодня невозможно (встроенные всегда есть), но допущение не защищено.
- 🟡 **`safety.py:22–23`** — два перекрывающихся regex для `del /s` (нит, осознанное дополнение).

### 3.3 Тесты

- 🟠 **`runner.py` ~60 %** покрытия — ветки repair-loop и обработки отказов недотестированы относительно критичности модуля.
- 🟠 **`ui.py` ~18 %** — практически не покрыт (Tk тяжело тестировать headless). Все остальные модули имеют реальное покрытие.
- 🟡 `planner.py` ~63 % — fallback retry-вариантов покрыт частично.
- Заметка: расхождение в числе тестов между снапшотами (`AGENTS.md` упоминает 325, фактический прогон на ветке — ~396) стоит синхронизировать в доке.

### 3.4 Документация

- В целом сильная и актуальная. Точечно:
  - 🟡 Цифры в `AGENTS.md`/`CHANGELOG.md` (число тестов, % покрытия) разъезжаются со снапшотами — освежить.
  - 🟡 Расположение скиллов описывается неоднозначно (встречается и `local_codex_lite/skills/`, и корневой `skills/`); фактически рабочий путь — **корневой `skills/`** (там `artifact-unpack`, `cve-bin-tool`, новый `appsechub`). Зафиксировать один канон.

### 3.5 Tooling / CI

- Состояние хорошее. Мелочи:
  - 🟡 Мутационное тестирование не гейтит PR (осознанно) — survivors копятся; стоит хотя бы трекать счёт в issue.
  - 🟡 Нет явного гварда минимальной версии Python при запуске (см. 3.2 про `datetime.UTC`).

## 4. Мусор и старьё (инвентаризация)

`.gitignore` корректно закрывает `__pycache__/`, `*.pyc`, `.coverage*`, `.local-codex-lite/`, кэши и временные `generated_projects/`, `scan_runs/`, `tmp_trufflehog/` (их в дереве нет — хорошо).

Кандидаты на чистку:

| Объект | Класс | Действие |
|---|---|---|
| `__pycache__/**`, `*.pyc` (вкл. `* (2).pyc`, `*.pyc.bak`, `ui...pyc.1316…`) | мусор, не в git | удалить локально (безопасно) |
| `.coverage` (корень) | артефакт, gitignored | удалить локально |
| `.git/*.lock.bak*`, `HEAD.lock.*` (**69 шт.**) | повреждения git-операций | **не удалять руками** → `git gc` / аккуратная чистка |
| `.git/objects/**/tmp_obj_*` (**225 шт.**) | осиротевшие git-объекты | **не удалять руками** → `git gc --prune=now` после бэкапа |
| `.local-codex-lite/patch.diff`, `preview.diff`, `task_history.json`, `ui_geometry.txt`, `config.yaml` | runtime-стейт | **оставить** |
| `*__MOVED_TO__*` маркеры (в `getiton/_el_triage`, не в этом репо) | — | вне области |

Правка `.gitignore`: добавить на всякий случай git-внутренности не нужно (их не коммитят), но имеет смысл вынести репозиторий из синхро-папки — см. план.

## 5. Поэтапный план исправлений

Каждая фаза — отдельный, обратимый шаг. **Старт только после согласования.**

**Фаза 0 — Защитить репозиторий (полчаса, наивысший приоритет)**
1. Сделать полный бэкап `.git` (zip) до любых операций.
2. Решить вопрос синхронизации: либо исключить `.git` и кэши из правил YandexDisk, либо (предпочтительно) **перенести рабочий клон вне папки синхронизации**, а синхронизировать только через `git push`/remote.
3. `git gc --prune=now` + `git fsck` для чистки 69 локов и 225 `tmp_obj_*` (после бэкапа).
4. Закоммитить/добавить `tests/test_runner_apply.py` (если он нужен) или удалить, если устарел.

**Фаза 1 — Безопасная чистка мусора (15 минут)**
5. Удалить локально `__pycache__/`, `*.pyc`, дубликаты `* (2).pyc`/`*.pyc.bak`/числовые суффиксы, `.coverage`. Проверить, что `.gitignore` их закрывает (закрывает).

**Фаза 2 — Мелкие безопасные дефекты (1–2 часа)**
6. Дружелюбный гвард версии Python: при старте, если `<3.11`, выводить понятное сообщение вместо `ImportError` от `datetime.UTC` (или ввести `UTC`-шим в одном месте).
7. Защитить `intent.py:71–73` от пустого списка capabilities.
8. Освежить цифры в `AGENTS.md`/`CHANGELOG.md` (тесты, покрытие) и зафиксировать канон расположения скиллов (`skills/`).
9. Решить судьбу мёртвой метадаты `executor` в `tool_registry.py`: либо реально использовать для диспатча, либо убрать поле.

**Фаза 3 — Покрытие критичных путей (0.5–1 день)**
10. Поднять `runner.py` до ≥75 %: тесты на repair-loop, отказ apply, восстановление из бэкапа, лимит `max_patch_attempts`.
11. Добрать ключевые retry-ветки `planner.py`.

**Фаза 4 — Рефактор `ui.py` (1–2 дня, по желанию)**
12. Вынести доменные эвристики (`cve_min_severity_for_task`, `should_create_project_workspace`, выбор воркспейса) из `ui.py` в тестируемый доменный модуль; оставить в UI только вьюху и обработчики. Это снимает и SoC-долг, и даёт покрытие без headless-Tk.
